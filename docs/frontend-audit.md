# Frontend audit — Phase 0

Verified locally on 2026-10-24. Source: `demo-ui/`; roadmap: `docs/roadmap (1).md`.

## Recovered implementation

- Python standard-library generator (`build.py`), static HTML, plain JavaScript and CSS. No React/Next.js application or package manifest exists in this export.
- Input: `content/characters.json` (41 entries), `content/guides.json` (8 entries).
- Output: 54 `dist/**/index.html` pages and `dist/data.js` (`window.ATLAS`).
- Routes are physical directories, served from the web root. Assets and links use absolute paths.
- Styles load in order: `style.css`, `pages.css`, `refined.css`, `game-theme.css`. Later files override earlier designs; preserve this order during migration.
- `dist/app.js` owns search dialog, directory filters, favorites, guide filters, rank picker and scroll observers. It is source material, not generated by `build.py`; keep it and CSS/assets when rebuilding.
- Favorites (`atlas-saved`) and ranks (`atlas-ranks`) are keyed by character name in browser storage. Preserve these keys until an explicit data migration exists.
- Export contains its own Git repository and Sites hosting metadata. Do not move its `.git` or copy hosting project identity into a new application.

## Page-to-API map

All game resources below use `/api/v1/games/stella-sora` as prefix.

| Page | Count | Existing data / interaction | Initial API |
| --- | ---: | --- | --- |
| `/` | 1 | Featured names, first 3 guides, counts; currently hardcoded | `/characters`, `/guides`; keep explicit featured slug configuration |
| `/characters/` | 1 | Name, element, rarity, portrait; filters and favorites | `/characters?q=&element=&rarity=&page=&limit=` |
| `/characters/:slug/` | 41 | Artwork, voice, source, related same-element entries | `/characters/:slug`, `/characters?element=` |
| `/guides/` | 1 | Title, description, category, minutes | `/guides?category=&page=&limit=` |
| `/guides/:slug/` | 8 | Ordered heading/paragraph pairs and next guide | `/guides/:slug` |
| `/tier-list/` | 1 | Full roster and local S/A/B/Unranked values | Paginated `/characters`; ranks remain local |
| `/about/` | 1 | Attribution and editorial policy | Static document initially |
| Search dialog | Shared | Client-side character/guide text search | Reuse catalog and guide lists for MVP; dedicated search deferred |

Pagination must be handled by the frontend: fetching only the first API page would break the current all-roster board and search. The server never accepts a public draft/status override.

## Data shape and gaps

Characters currently have `name`, `slug`, `element`, `rarity`, `portrait`, `image`, `voice`, `official`, `source`. Empty voice strings become nullable values at the API boundary. `official` describes source availability, not publication approval. No roles, skills, stats, equipment or tested builds exist. Do not fabricate them.

Guides have `slug`, `title`, `category`, `description`, `minutes`, and ordered `sections: [heading, paragraph][]`. Migrate these to structured editor documents through an explicit importer. Guides currently have no stable IDs, revisions, author IDs, publication records or patch applicability. The date in generated HTML is hardcoded and must not be imported as verified provenance.

Counts verified: 41 characters, 8 guides, 54 HTML pages, 0 missing character image/portrait references (82 checked). Local Poppins/Oswald files and OFL license files are present. Binary font identity and artwork redistribution rights have not been independently verified.

## Migration plan

1. Keep `demo-ui` intact as the reference export. Add workspace infrastructure beside it.
2. Add `apps/api`, PostgreSQL, migrations and verification before changing public rendering.
3. Add `apps/web` when integrating APIs; preserve routes, assets, style order, keyboard search and local storage behavior. Decide on Next.js in a separate implementation ADR.
4. Import a reviewed subset of catalog fixtures with source URLs; do not mark the whole export freshly verified.
5. Add `apps/admin` for authenticated editorial work after identity protection exists.
6. Replace static catalog and guides incrementally. Retire the Python generation path only after route/data parity is verified.

## Verification limits

This audit checks source and filesystem inventory. It does not assert browser rendering, accessibility compliance, external-source accuracy, successful deployment or backend functionality. No backend exists yet. Node 24 and Python 3.11 are available; `pnpm` is not currently on PATH.
